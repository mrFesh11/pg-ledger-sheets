# pg-ledger-sheets

[![ci](https://github.com/mrFesh11/pg-ledger-sheets/actions/workflows/ci.yml/badge.svg)](https://github.com/mrFesh11/pg-ledger-sheets/actions/workflows/ci.yml)

**English.** A small tool that keeps a Google Sheets ledger in sync with a Postgres table: every new row is appended once, each finished day gets a "day total" line, and a summary sheet with monthly formulas grows by itself. What goes where is described by a *profile* — a plain Python module with an SQL query and a few functions. A ready profile for the [Bedolaga](https://github.com/BEDOLAGA-DEV/remnawave-bedolaga-telegram-bot) Telegram bot (Remnawave VPN billing) is included; the rest of this README is in Russian.

---

Выгрузка операций из Postgres в Google-таблицу для тех, кому отчётность нужна в привычном виде: бухгалтеру, партнёру, инвестору. Скрипт запускается по таймеру, дописывает новые строки, подводит итог за каждый закрытый день и ведёт лист с месячными итогами на формулах. База открывается только на чтение.

Что именно выгружать, описывает **профиль** — обычный Python-модуль: SQL-запрос, раскладка строк по листам и правило подсчёта выручки. В комплекте готовый профиль для бота [Бедолага](https://github.com/BEDOLAGA-DEV/remnawave-bedolaga-telegram-bot) и минимальный пример [examples/orders.py](examples/orders.py).

## Что гарантирует ядро

- **Строка попадает в лист один раз.** Последний столбец каждого листа — ID записи; перед записью скрипт читает его и пропускает то, что уже есть. Повторный запуск после падения на середине ничего не дублирует.
- **Запись не теряется, даже если закоммичена «задним числом».** Выборка всегда идёт с перекрытием: последние 1000 идентификаторов и двое суток назад. Незавершённые записи запоминаются и перепроверяются 7 дней.
- **Итог дня ставится один раз и только за закрытый день** — через 15 минут после полуночи в часовом поясе профиля. Какие дни уже закрыты, скрипт узнаёт из самого листа, а сумму пересчитывает по базе.
- **Никаких формул из базы.** Данные пишутся как `RAW`: описание платежа вида `=IMPORTXML(...)` останется текстом. Формулы есть только в листах, которые строит сам профиль.
- **База только на чтение**: соединение открывается с `default_transaction_read_only=on` и таймаутом запроса; для Бедолаги есть скрипт роли с доступом к нужным столбцам двух таблиц.
- Блокировка от параллельного запуска, состояние сохраняется атомарно с `fsync`.

## Профиль Бедолаги

Листы: «Оплаты» (всё, что меняло баланс), «Покупки» (на что баланс потрачен), «Расходы» (ведётся руками), «Итоги», «По способам оплаты», «По статьям расходов».

У Бедолаги балансовая модель: клиент пополняет баланс, с баланса списываются подписки. Поэтому выручка считается по деньгам, пришедшим извне:

| Тип строки | Условие | В выручку |
|---|---|---|
| Оплата | `deposit`, `subscription_payment`, `gift_payment` с настоящим платёжным шлюзом | + сумма |
| Возврат | `refund` через шлюз | − сумма |
| Ручное зачисление | `deposit` со способом `manual` | 0 |
| Бонус | промокоды, опросы, прочие зачисления без шлюза | 0 |
| Рефералка | `referral_reward` и реферальные зачисления | 0 |
| Покупка | списание с баланса — уходит на лист «Покупки» | 0 |

Ручные зачисления, бонусы и рефералка видны в таблице и в «Итогах» отдельными колонками, но в выручку не входят: живых денег за ними нет.

Известные ограничения: подарочные подписки, оплаченные шлюзом напрямую (таблица `guest_purchases`), бот не проводит через `transactions`, и в выгрузку они не попадают; дата операции — время подтверждения платежа, около полуночи она может на день разойтись с админкой бота.

## Запуск

Нужны Python 3.12+ и [uv](https://docs.astral.sh/uv/) либо Docker.

1. В Google Cloud создайте сервисный аккаунт, включите Google Sheets API, скачайте JSON-ключ.
2. Создайте пустую таблицу и дайте сервисному аккаунту права редактора. ID таблицы — часть ссылки между `/d/` и `/edit`.
3. Задайте переменные и запустите:

```bash
export LEDGER_DSN=postgresql://ledger_ro:пароль@localhost:5432/remnawave_bot
export LEDGER_SHEET_ID=...
export LEDGER_KEY=/path/to/service-account.json
export LEDGER_STATE=/var/lib/pg-ledger-sheets/state.json

uv run pg-ledger-sheets init   # создать листы, заголовки и форматы (один раз)
uv run pg-ledger-sheets sync   # дописать новое; ставится на таймер
```

Посмотреть результат без Google: `uv run --extra xlsx pg-ledger-sheets xlsx отчёт.xlsx`.

| Переменная | Назначение |
|---|---|
| `LEDGER_DSN` | строка подключения к Postgres |
| `LEDGER_SHEET_ID` | ID Google-таблицы |
| `LEDGER_KEY` | путь к JSON-ключу сервисного аккаунта |
| `LEDGER_STATE` | файл состояния (рядом создаётся `.lock`) |
| `LEDGER_PROFILE` | модуль профиля, по умолчанию `pg_ledger_sheets.profiles.bedolaga` |
| `LEDGER_SINCE` | необязательная дата `ГГГГ-ММ-ДД`: более раннюю историю не выгружать. Задаётся до первого запуска и потом не меняется, иначе старые строки допишутся в конец |

### На сервере рядом с ботом

В [deploy/](deploy/) — unit и таймер systemd, запускающие контейнер раз в 10 минут: файловая система только для чтения, без capabilities, под непривилегированным пользователем. Для Бедолаги установка в одну команду (создаёт роль `ledger_ro`, собирает образ, пишет `/etc/pg-ledger-sheets/env`):

```bash
install -D -m 400 service-account.json /etc/pg-ledger-sheets/service-account.json
deploy/bedolaga/install.sh <sheet_id> <docker-сеть бота>
```

Дальше один раз создать листы и включить таймер:

```bash
docker run --rm --network "$(sed -n 's/^LEDGER_NETWORK=//p' /etc/pg-ledger-sheets/env)" --env-file /etc/pg-ledger-sheets/env -v /etc/pg-ledger-sheets/service-account.json:/key.json:ro pg-ledger-sheets init
```

```bash
systemctl enable --now pg-ledger-sheets.timer
```

Значения в `env` пишутся без кавычек; `LEDGER_NETWORK` (docker-сеть, в которой виден Postgres) обязателен.

## Свой профиль

Профиль — модуль с переменной `PROFILE` типа `pg_ledger_sheets.core.Profile`. Полный рабочий пример — [examples/orders.py](examples/orders.py). Главное:

```python
SOURCE = """
    select p.id, coalesce(p.settled_at, p.created_at) as at, p.status <> 'pending' as done, p.status, p.customer, p.amount_cents
    from payments p
"""


def route(record: Record) -> tuple[str, list[Cell]] | None:
    if record.data["status"] == "failed":
        return None
    ...
    return "Payments", [day, clock, record.data["status"], record.data["customer"], amount, record.id]
```

Соглашения:

- запрос обязан вернуть `id` (растущий целочисленный ключ), `at` (`timestamp` или `timestamptz`, не NULL) и `done` (запись окончательна); остальные столбцы попадут в `record.data`. Запрос пишется без `;` в конце и с уникальными именами столбцов, знак `%` удваивается;
- таблица только дополняется: запись с `done = true` считается неизменной. Возврат или исправление — это новая строка в источнике, а не смена статуса старой;
- `route` возвращает название листа и строку либо `None`, если запись не нужна;
- строка совпадает по ширине с заголовком листа, первый столбец — дата, последний — `id` записи (ядро это проверяет);
- `revenue` отдаёт вклад записи в итог дня в минимальных единицах (копейки, центы);
- `ledger` — лист, в котором подводятся итоги дня; `kind_column` (номер столбца с нуля) и `total_label` говорят, по какому столбцу и значению отличать строку итога;
- `month_row` и `summary_total` возвращают строки листа итогов с формулами; разделитель аргументов зависит от локали таблицы и приходит параметром.

Запуск из корня репозитория: `LEDGER_PROFILE=orders PYTHONPATH=examples uv run pg-ledger-sheets sync`. В Docker свой профиль монтируется: `-v ./examples:/profiles:ro -e PYTHONPATH=/profiles -e LEDGER_PROFILE=orders`.

## Разработка

```bash
uv sync
uv run ruff check . && uv run pyright && uv run pytest -q
```

Логика «что дописать в таблицу» — чистая функция `plan()` в [core.py](pg_ledger_sheets/core.py): на вход записи из базы и то, что уже есть в листе, на выход строки и новое состояние. Тесты покрывают её без базы и без Google.
